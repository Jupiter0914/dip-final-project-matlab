# 固定工作量轨迹核对

参考和快速入口分别从内存中的二值蒙版开始，真实运行至自然停止或八轮上限，同时记录每次交付的 PM31。验证器先逐次比对两个生产入口的状态、失败原因、初始候选和分配、完整动作与接收文件。接下来再运行诊断轨迹，并在种子、每次接受动作、无改善退出和最终文件处与这两次真实生产调用对照。

参考诊断独立重新绘制每个单删、单插候选，枚举全部满足三角与相邻边约束的合法组合，按完整冻结键排序。对于前 24 项，最终联合形状、逐环 XOR 和完整掩模的真 XOR 逐项重算。连续几何与数字对应的检查都记录在诊断摘要内。以实际生产 exchangeStep 的诊断输出和接受动作为另一重约束，避免参考诊断自身形成一个与原生产路径不同的规则。

快速诊断记录实际生产逻辑计算出的单项费用、原稠密下标、eligible 数量、前 24 项的全部并列键、最终可加分数与复查顺序，并直接比对被检候选的真 XOR 及失败原因。对没有进入快速完整复查的提案，从它实际给出的组合重新画全图，记录可核对的金标准。快速算法没有对这些提案作出的几何决定，不解释为快速算法已执行该检查。每轮额外检查缓存的环版本、重建和复用范围以及接受后的失效范围。每次新的生产调用从空缓存开始。

开发回归包括 512 种 3×3、8 个具名夹具及 36 个登记开发源，各运行四种方法。附加检查覆盖三角同圈替换、贴边和窄通道、空图、超出支持范围、预算下界、有限池无解与两圈翻转交集相消。旧 300 源只在候选确定后进行独立回归，运行前核验 selected_kernel.json 锁定的文件摘要。每次调用和轮次的计数、初末编码摘要和详细候选摘要分别写入 equivalence_calls.csv、equivalence_rounds.csv，任何不匹配立即保存首个可定位见证并使进程以失败退出。

开发核查的首次运行在两个都为空的缓存复用集合处停止。两者分别为 MATLAB 的 0×0 和 0×1 数组。诊断端将两边统一成列向量后重新从首个样例执行，比较的元素及其顺序保持严格相等。性能内核未因该检查改变。

```powershell
matlab -singleCompThread -batch "addpath('performance/validation'); runEquivalence('dev','dev1')"
matlab -singleCompThread -batch "addpath('performance/validation'); runEquivalence('old300','old300')"
```

第一条在开发数据恢复后执行，第二条另外需要已锁定内核和旧 300 个原始源。门槛判断使用本次真实产生的 equivalence.json。


## 轮一开发实测

四种方法在 520 个合成与具名夹具及 36 个开发源上共执行 2,224 次。逐一比较 2,978 次实际交付和 2,348 轮，未发现语义差异。共核对 61,118 个单删、68,021 个单插、3,633,595 个合法组合计数、19,056 个进入前 24 的组合，以及 754 个真正进入完整复查的组合。快速路径重建环缓存 2,931 次，复用 318 次。接受 20 次跨环和 734 次圈内操作。人工构造的三角形仅在单独夹具中触发本圈替点，主网格中三角替点计数为 0。[轮一回执](../perf_results/dev1/equivalence.json) · [内核摘要](../perf_results/dev1/kernel_stamp.json)

后续旧组核对从两次真实生产调用取得动作及二进制文件。在诊断中重建全部单项、所有合法组合的排序和前 24 项完整 XOR，核对独立排序所得的真实复检顺序；几何与数字对应在实际搜索到达候选时执行。每个快速侧提案先记录并逐点检查有序坐标，再用该侧自己的联合多边形调用完整 renderRings 计算原尺寸 XOR，逐项比较独立的参考值。即便该项未进入生产完整复查，也保留这次额外光栅实测。逐轮表另列两侧排序摘要和 PM31 摘要；逐检查点 CSV 给出两侧独立摘要、XOR 与字节数。去重真实文件放在 local/perf/validation_blobs。维护原始 300 源的只读图像恢复位置，就能使用下面的命令独立重读全部文件和数字结构，全程不运行优化搜索。

```powershell
matlab -singleCompThread -batch "addpath('performance/validation'); replayEquivalence('old300')"
```


旧 300 源还可分成两个互斥的原始清单奇偶行分片。该模式只适用于非计时验证。两个进程各限单线程，各自保存逐源、逐轮与检查点表，按内容寻址的输出先写私有临时文件才发布。用完两个分片后执行合并入口，检查两侧锁定文件摘要、每片准确 150 个预定源和 600 个调用、每份 CSV 的回放摘要，并逐文件重验总体 300 源与 1,200 个唯一调用。串行入口无需任何分片。

```powershell
matlab -singleCompThread -batch "addpath('performance/validation'); runEquivalence('old300','old300',1,2)"
matlab -singleCompThread -batch "addpath('performance/validation'); runEquivalence('old300','old300',2,2)"
matlab -singleCompThread -batch "addpath('performance/validation'); mergeEquivalenceShards('old300')"
```


## 第二轮边界故障见证

单行（1×16）、单列、1×1、跨全宽的贴边环加入第二轮验收。在 efSingleChanges 摘要 700a3f69… 的初版中，1×16 输入两次均无翻转的编辑在事件累计处因空数组形状抛出异常。另一中间版本 d4a4cfb2… 仍会在合并翻转与边线索引处产生向量维度错误。原图大小、确切四倍坐标、两个编辑及金标准保留在 [合成故障见证](../perf_results/dev2/adversarial_mismatch.json)。修订统一单区间、空区间、全局像素查表的向量方向。影像、编辑集合、排序和结构门槛在整个对照中保持一致。这些修订均在第二轮工程计时前完成。


## 第二轮开发实测与存盘复算

修正版 efSingleChanges 的 SHA-256 为 aafd59d934e7f1cc0e14efc41219168fd1249ccc79f5064e94c59c3ff1290324。520 个合成及具名夹具与 36 个开发源的 2,224 次调用、2,348 轮和 2,978 个交付文件全部与参考实现一致。逐原幅线性编号核对了 129,139 次删插中的 5,988,110 个翻转像素，零差异，未触发容量回退。单独的 117 条合成对抗路径还验证了 234 次改动、2,790 个翻转像素及 4 个两环抵消像素，包含单行、单列、1×1、整幅贴边、扫描线恰过顶点、两点多重线迹与半格并列。

由独立复算入口在磁盘上重新读取 1,640 个不同 PM31，核对 2,978 次实际交付的两侧 SHA、字节数、原尺寸 XOR、环树和数字结构。2,348 个逐轮字节摘要和逐轮候选摘要均完全相等。[运行回执](../perf_results/dev2/equivalence.json) · [实际文件重放](../perf_results/dev2/equivalence_replay.json) · [检查点清单](../perf_results/dev2/equivalence_checkpoints.csv)
